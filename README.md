# 卫戍协议 · 规程｜谢拉格冻结叠层 一图流

一个**非官方、非盈利**的《明日方舟》「卫戍协议：规程」攻略海报。

- 在线版：<https://sp-guide.pages.dev/>
- GitHub 镜像 / 源码仓库：<https://github.com/mario02222227/sp-guide>（Pages：<https://mario02222227.github.io/sp-guide/>，国内首屏较慢，优先用上面的 Cloudflare）

- 固定 **4:3** 画布：设计分辨率 **1600 × 1200**
- 屏幕按视口整体等比缩放，不重排、不滚动
- 导出 **3200 × 2400 PNG**
- 视觉：参考图同款的工业红黑主题——卡其 / 亮红 / 暗红底、黑色标题条幅、`РЕГЛАМЕНТ` 西里尔标签、六边形金属核心框、金色取景框角标；品阶色保留为内边框，朝向用贴边金色三角表示。
- 可编辑文字、拖动站位、替换装备 / 路线头像、装备库拖拽、战场地图图鉴、导入 / 导出数据
- 分享：阵容链接 / 二维码 / 竖版长图，别人打开就是你这一版
- 手机可「放大」到 1600 × 1200 原尺寸阅读
- 可选在导出的海报 / 竖版长图上印入口二维码（默认关闭）；可打包成单个离线 HTML
- 内容和素材都可离线使用

直接双击 [index.html](index.html)，或双击 [打开攻略.bat](打开攻略.bat)。

## 1. 使用

### 看

- 点任意干员头像 / 棋子：打开详情弹层，看 **费用、基础数值、攻击范围、三个技能、模组、天赋、羁绊**。
- 技能卡上会标 **Ⅰ / Ⅱ / Ⅲ**；海报头像下方显示当前技能与 **X / Y 模组类型标**。
- 模组默认展示所选模组的 **3 级效果**（属性加成 + 效果）；有多个模组的干员可在详情里像技能一样点选切换（含部分干员的特限证章），数据来自可露希尔Wiki 模组页。
- 羁绊行显示 **当前人数 / 已达到的档位阈值**：例如 4 谢拉格显示 `4 / 3`，6 谢拉格显示 `6 / 6`；不再显示「满」。
- 鼠标悬浮羁绊行：原生 tooltip 显示该羁绊的完整效果。
- 特质 / 羁绊效果里的 **【羁绊】**、**“装备”名** 和开头的 **特质类型词**（持续叠加 / 整备能力等）可以直接点：
  - 羁绊浮层显示档位效果 + **含有的干员**（区分棋盘上 / 名册内，点头像看详情）；
  - 装备浮层显示基础 / 进阶效果 + **本套装备于**哪些干员；
  - 特质类型浮层列出名册内同类型特质的干员。
  - 所有词条共用一个浮层：点新词条是替换内容，不会叠出无限层；最多保留 3 层历史，可用 **← 返回** 逐层退回。
  - 手机端词条浮层盖在干员详情上方；点浮层外面只关闭浮层，不会误触下面的棋子 / 羁绊行。
- 战斗地图：顶栏「战场地图」打开 PRTS 地图一览（#01-#06、#09-#12，共 10 张 × 3 场地；#07/#08 缺失）；可切换场地、看地形/装置说明，并打开/下载拼接长图。
- 右上角「导出一图流」：生成 3200 × 2400 PNG 并直接下载（不再先弹预览窗）。

### 分享 / 放大 / 帮助

- 顶栏「分享」：生成当前阵容的链接和二维码。链接编码的是**改动部分**，打开就是同一套站位、技能、装备、盟约；可复制链接、下载二维码 PNG、下载竖版长图。
- 竖版长图 1080 × 2160（导出 2160 × 4320）：该带谁 / 站位 / 每阶段抓谁 / 缺卡怎么办，适合手机、小红书和群聊。
- 入口二维码默认**不印**：在「分享 → 海报 / 长图入口二维码」里勾选才会印到标题右侧；不勾时页头保持干净。开启后留空链接则用当前页面地址，`file://` 本地打开时不会生成。
- 手机看不清：点右下角「放大」或双击海报，按 1600 × 1200 原尺寸展开，拖动查看；Esc 或再点一次退出。第一次在窄屏打开会有一次提示。
- 顶栏「?」：三步上手说明，以及本套每条「缺卡替代」的汇总。
- 缺卡信息有三处，来自同一份数据：海报棋盘下方「缺卡」一行、棋子详情里的「替补 / 没有怎么办」、竖版长图的「缺卡怎么办」。

### 地图与站位

PRTS 的战场一览只提供地形图，**没有每个地图的推荐站位坐标**；本工具不伪造这些坐标。当前提供：

- 10 张地图 × 3 个场地的原图图鉴，标注地图装置 / 特殊地形。
- 一张拼接长图 [docs/maps-atlas.webp](docs/maps-atlas.webp)，在「战场地图」里可直接打开 / 下载。
- 单文件版（`dist/`）会把 30 张地图一起内联，离线也能看；拼接长图只在网页版提供。
- 本套 8 人的通用站位仍以海报棋盘为准；地图专属站位需要按实际地形自行落位。若后续要「每张地图拖拽站位并导出」，可以在这个图鉴上继续扩展。

### 改

1. 点右上角「编辑」。
2. 直接点画布上的标题、标签、定位字、路线提示、说明框改字。
3. 拖干员到棋盘只是**放入**；松手后棋子进入选向状态（冷青色描边，和金 / 橙 / 紫的品阶边框不会混，提示「按住拖动选方向」）。再**按住这个棋子向外拖动**，格子内出现朝向箭头和攻击范围预览，松手确定朝向。若这两步之间点了其他地方，本次放入会自动撤销。
4. 拖动已上场的棋子到别的格子；拖到已有干员的格子会交换位置，落点后同样进入选向状态。
5. 点装备图标：弹出装备选择器，左侧图标、右侧显示名称 / 基础效果 / 进阶效果，点「装备到此格」确认；点空格的「+」也可添加，单列最多 3 件。也可以点编辑栏的 **「装备库」**，右侧装备库同样会显示效果，并可把图标拖到装备格。
6. 成型节奏只保留「阵容」：点阶段里的头像替换，行末「+」添加，最多 9 人；下方文字框写这一阶段的一句话，例如「升 3 本抓灵知」。
7. 点干员头像打开详情；**在左侧干员库里双击干员**也会打开详情。编辑模式下可点 **「设为携带」** 切换 Ⅰ / Ⅱ / Ⅲ 技能。
8. 编辑模式下点棋子右上角箭头：按 上 / 下 / 左 / 右 4 个方向循环旋转朝向；箭头也会进入导出图。
9. 右上角区域标为 **「核心干员」**，不再显示「主叠层 / 冻结」这类定位文字；核心干员也不再自动收录：把干员放上棋盘后，点棋子上的 **☆** 或详情里的 **「加入右上角」** 才会出现在海报右上角；点 **★** / 卡片右上角 **×** 移出，最多 6 人。
10. 盟约策略：选择器左侧列表、右侧显示完整效果，确认后才加入；主盟约点「删除盟约」，次选点卡片右上角 **×**，删除主盟约时第一个次选自动顶上。海报放不下的长效果会自动使用本地精要版，完整文本仍在选择器和详情里，不再要求手填海报摘要。
11. 改错了按 **Ctrl+Z** 撤销、**Ctrl+Y**（或 Ctrl+Shift+Z）重做，也可以点编辑栏最左边的两个箭头；手机编辑时箭头在顶栏。最多回退 80 步，站位、装备、盟约、文字、棋盘大小、新建 / 导入 / 恢复示例 / 载入存档都能退；连续敲同一段文字算一步。光标在文字框里时 Ctrl+Z 走浏览器自带的文字撤销。历史只在当前页面里，刷新后清空。
12. 改完点「完成」。所有改动自动保存在本机浏览器。

编辑栏「棋盘」可以改棋盘大小（6–12 列 × 4–6 行），用于对照战场地图放大格子、按实际地形落位；缩小棋盘时超出范围的棋子会被移除，改动前会先写自动备份。

编辑装饰（虚线框、字数计数、加号、核心星标、选向提示）只用于屏幕，**不会进入导出图**。

### 从零新建 / 干员库 / 装备库 / 变阵 / 存档

编辑栏按用途分成四组：**撤销 / 重做** ｜ **干员库 · 装备库 · 备选 · 棋盘** ｜ **新建 · 存档 · 导入 · 导出数据** ｜ **恢复示例**。

- **新建**：新建空白阵容。当前内容会先写入「自动备份」，然后打开干员库。海报标题会变成「未命名阵容」，8×4 空棋盘，装备 / 路线 / 羁绊从零开始。
- **干员库**：左侧弹出干员列表，内置 **141 人名册**（66 名重叠 + 75 名当期补录，含塔露拉）；75 名补录仍有攻击范围格/模组效果缺失，显示「暂无数据」。每行只留头像和名字，并在行内直接显示 **核心盟约 / 附加盟约**（核心带金色描边与「核心」标签）和 **基础特质**（含类型标签：持续叠加 / 单次叠加 / 作战能力 / 整备能力 / 特异化，最多 4 行，悬停看全文），不用点开详情就能比较；手机端干员库也是同样的卡片行（点整行看详情 / 放置）。可按 **特质 / 触发 / 羁绊 / 名字** 筛选（已去掉职业、星级；羁绊拆成「核心盟约」「附加盟约」两排，核心 10 个：炎、萨尔贡、维多利亚、谢拉格、阿戈尔、叙拉古、卡西米尔、乌萨斯、伊比利亚、莱塔尼亚；多选时结果只保留一个列表，选中项以标签显示，不再出现「同时命中 / 只命中」分组）；**双击** 看基础数值、攻击范围、技能、模组——桌面端在右侧抽屉里打开（不弹窗、海报自动让位），手机端仍是全屏卡片；拖到棋盘格子，或点选干员后点棋盘格子放置。特质筛选取自特质文本开头的类型词：持续叠加 / 单次叠加 / 作战能力 / 整备能力 / 特异化。
- **装备库**：右侧弹出 16 件装备的图标库，可搜索；点图标会在上方显示名称、基础效果、进阶效果和当前使用处数；拖到棋盘下方「必做 / 大提升 / 可选」装备格即可替换。
- **变阵**：右侧弹出面板，显示「当前阵容」「备选 / 未上场」「变阵存档」。备选可以直接拖 / 点选上场；存档可以加载、覆盖、删除。
- **存档**：给当前海报命名保存；支持加载、覆盖、删除。最多 12 个手动存档，另有一个「自动备份」槽位。

> **编辑到一半怎么办？** 当前草稿会自动保存。顶栏的状态点有四种：空心「改动自动保存在本机」= 打开后还没改过；金色「保存中…」= 文字改动等待写入；绿色「已自动保存 HH:MM」= 已写入；红色「未保存」= 本机存储写入失败（存储已满或隐私模式），这时请先「导出数据」。想留版本时再点「存档」保存命名版本；新建 / 载入前都会先写自动备份。
>
> 存档与当前草稿是分开的：存档 key 为 `sp-guide-poster-saves-v1`，当前草稿 key 为 `sp-guide-poster-v2`。导出的 JSON 只包含当前海报，不包含存档列表。

### 数据备份

编辑模式底部：

- **导入数据 / 导出数据**：当前海报 JSON，换设备用。
- **恢复示例**：先备份当前数据，再恢复示例。

导入 / 恢复示例 / 打开分享链接之前写的备份（`sp-guide-poster-v2-before-*-backup-<时间>`，每类最多留 3 份）存的是和「导出数据」同一种精简 JSON（约 4KB），可以直接用「导入」读回来。

### 传播与分发

这一页的目标是「别人能抄、能改、能再发」。

1. **托管**：纯静态，仓库丢到 GitHub Pages / Cloudflare Pages 即可；用 `http(s)` 打开后可在分享弹层里决定要不要印入口二维码。步骤见 [DEPLOY.md](DEPLOY.md)，不用租服务器。
2. **单文件 HTML**：`node tools/build-single.mjs` 生成 `dist/卫戍协议一图流.html`（约 4 MB，图片全内联）。QQ 群文件发这个文件，双击就能离线用，不用教人部署。
3. **分享码**：顶栏「分享」把阵容压进 URL hash，改完再复制就是新版本；链接只存改动，默认阵容只有几十个字符。
4. **竖版长图**：手机端传播的主力素材；海报是 4:3，长图是 9:20，信息重排、字号更大。
5. **模板署名**：用「帮助 → 用空白模板开始」新建时，页脚会自动写「模板 · 卫戍协议一图流」；别的作者用这个模板出图，图上会带着模板出处。自己的署名改页脚作者字段。
6. **二维码（可选）**：默认关闭；需要时在「分享」里勾选，海报头部右侧才会出现入口块（74 px）。入口链接建议用短链（≤ 25 字符），在 3200 px 导出图里更清楚。

## 2. 数据版本与旧存档迁移

当前数据格式：

```js
schemaVersion: 3
```

运行时仍保留 v2 兼容视图（`route` / `bonds`），但**不写入 v3 存储**。v3 实际存储：

```js
{
  schemaVersion: 3,
  meta,
  coreOperators: [{ operatorId, role }],
  board: { cols, rows, placements: [{ operatorId, col, row, facing }] },
  stages: [{ id, label, recruit, lineupSource, lineup, note }],
  bondPlay: { [bondId]: string },       // 只存用户改动/清空
  equipment,
  equipmentNotes,
  strategy, // { main, alternatives, reason, posterText }
  loadout: { [operatorId]: skillIdx },
  operatorOverrides: { [operatorId]: { name, avatar, role, ... } },
  legacy: { route, bonds, notes, strategyAlternatives }
}
```

游戏数据（`operators`、`bondLibrary`、`strategyLibrary`、`trait`、`effects`、`thresholds` 等）总是从 `data/stronghold.js`、`data/closure.js` 重建。

旧版长页面存档（key：`sp-guide-03-v1`）打开时：

1. 自动调用 `migrate(oldData)`；
2. 迁移后的新结构保存到 `sp-guide-poster-v2`；
3. 旧数据备份到 `sp-guide-03-v1-backup-{时间}`；
4. 无法迁移时备份到 `sp-guide-03-v1-failed-backup-{时间}`，并回退示例数据，toast 提示。

旧版里没有直接对应关系的长文本会保存在迁移结果的 `legacy` 字段中，不进入海报，但不会被静默删除。

### 配色令牌

颜色集中在 `styles.css` 顶部的 `:root`，主题层 `regulation-theme.css` 只覆盖其中几项：

| 令牌 | 含义 | 用在哪 |
| --- | --- | --- |
| `--accent` / `--accent-rgb` | 主强调 · 金 | 主按钮、标题、已选中的筛选项、已达成的羁绊、可落格 |
| `--accent-2` / `--accent-2-rgb` | 次强调 · 橙 | 次级标签、编辑态的「+」添加入口 |
| `--focus` / `--focus-rgb` | 冷青色 | 只给屏幕上的瞬时交互态：键盘焦点环、待定朝向的棋子、已拿起的干员、正在选的格子。不会出现在导出图里 |
| `--red` | 危险 / 超限 | 删除、移出、字数超限、保存失败 |
| `--on-accent` | 压在金 / 橙实底上的文字 | 主按钮文字 |

半透明色一律写成 `rgba(var(--accent-rgb), .12)`，不要再写死 `rgba(246,182,30,.12)`：换主题时只改三元组，描边 / 底色 / 光晕一起变。界面（抽屉、弹窗、详情）里的字最小 11px；海报内的字最小 20px（`posterCheck()` 会检查）。

### 批量改内容

编辑 `data.js`，刷新页面。注意：

- 站位是 `{ operatorId, col, row, facing }`，不存像素坐标。
- 当前展示用 `stages` 三段；旧 14 行路线保存在 `legacy.route`。
- 装备三档：`must` / `big` / `optional`，每格最多 3 个图标。
- 旧 NOTES 不再显示，内容已迁移到 `legacy.notes`，不丢失。
- 旧路线提示已迁到 `legacy.route`；旧次选超过 2 个的迁到 `legacy.strategyAlternatives`。

### 换图

1. 替换 `assets/avatars/`、`assets/items/` 或 `assets/bonds/` 里的图片（保持文件名）。
2. 运行：

```bash
node tools/embed-assets.mjs
```

也可以不运行，网页会加载原文件；但导出时 `html-to-image` 对本地文件 / 远程图片可能有限制，**建议重新生成**。

3. 如果要发单文件，再跑一次 `node tools/build-single.mjs`。

## 4. 导出实现

- 屏幕：`.poster` 固定 1600 × 1200，外层只做 `transform: scale()`，不改变内部布局。
- 导出：临时移除 `.poster` 的 scale，加 `.is-exporting` 隐藏编辑装饰，等 `document.fonts.ready`，用本地 `html-to-image` 以 `pixelRatio: 2` 输出 3200 × 2400。
- 海报内部不使用 `backdrop-filter`、`mask`、`mix-blend-mode`、`blur`；素材是 data URL，无跨域。
